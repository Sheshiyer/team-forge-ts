## What remains unscoped and why

1. **All Rust `ShellExt` calls bypass capability ACL.** This is a Tauri v2 runtime behavior, not a configuration gap. The capabilities created in T-002 document the intended security contract and protect JS-side `@tauri-apps/plugin-shell` IPC, but Rust `app_handle.shell().command(...)` and `.shell().open(...)` execute without capability validation.

2. **`launch_paperclip_script_internal` can launch arbitrary scripts.** The `paperclip-singleton.json` capability scopes to `launch-thoughtseed-paperclip.sh` only, but the Rust function accepts any `script_path` parameter and uses `/bin/zsh` as interpreter for shell scripts. This is accepted because:
   - TeamForge is operator surface only (bridge B)
   - The singleton constraint means one shared Paperclip instance for all orgs
   - No per-org capabilities are created
   - Paperclip is NOT converted to a Tauri sidecar

3. **`cmd` path resolution mismatch.** `resolve_node_binary()` and `resolve_bash_binary()` may return absolute paths (`/opt/homebrew/bin/node`, `/bin/bash`). The capabilities use bare command names (`node`, `bash`) which only match the fallback case. For JS-side scoped calls to work, the command name in the capability would need to match the resolved path exactly, or the JS call would need to use the capability `name` (not the binary path). This is a known limitation documented in T-001 discovery #7.

4. **`shell:allow-open` URL scoping is in `tauri.conf.json`, not capabilities.** The current `tauri.conf.json` has `plugins.shell.open: true` with the permissive default regex. Narrowing this regex (e.g., to `^https?://.+`) is a T-003 candidate.

## Edge cases and follow-up (T-003+)

1. **T-003: Narrow `tauri.conf.json` `shell.open` regex.** Change `plugins.shell.open` from `true` to a custom regex that only allows `http://` and `https://` (e.g., `"^https?://.+"`). This would scope JS-side `shell.open` to web URLs only. Local file opens would need a separate `file://` regex or migration to `tauri-plugin-opener`.

2. **T-003: Rust-side shell enforcement.** Investigate whether Tauri v2 shell plugin can be patched or configured to enforce capability scopes for `ShellExt` Rust calls. If not, consider wrapping all Rust shell calls in a custom validation layer that checks against the same capability JSONs at runtime.

3. **T-003: `launch_paperclip_script_internal` script path validation.** The function currently resolves any user-provided script path. Consider adding an allowlist check against known Paperclip scripts (`launch-thoughtseed-paperclip.sh`, `paperclip-runtime-adapter.mjs`, etc.) before spawning.

4. **T-003: `resolve_node_binary()` / `resolve_bash_binary()` capability alignment.** If JS-side scoped shell calls are ever needed, the capability `cmd` fields must match the resolved absolute paths. Consider using `$RESOURCE` or `$HOME` variables in capabilities, or standardizing on bare command names with PATH augmentation.

5. **T-003: Remove `#[allow(deprecated)]` on `shell().open()`.** The Tauri shell `open` API is deprecated since v2.1.0 in favor of `tauri-plugin-opener`. Migrating would also change the scoping model (opener plugin uses its own permission/scope system).
